# ВАТРА — доставка кодів авторизації

Код застосунку вже використовує `supabase.auth.signInWithOtp` та `verifyOtp` через `vatra-backend.js`, без зберігання секретних кодів у браузері чи у власній SQL-таблиці. Ці шаблони є вихідними файлами конфігурації — **GitHub Pages не застосовує їх до Supabase автоматично**.

## Пошта — обов'язкові налаштування адміністратора

1. Перевірити власний підтверджений домен для пошти у вашому SMTP-провайдері.
2. У Supabase → Authentication → SMTP Settings налаштувати SMTP host, порт, логін, пароль, адресу відправника з вашого підтвердженого домену та **Sender name: ВАТРА**. Паролі та API-ключі не зберігати у репозиторії.
3. У Authentication → Email Templates вставити вміст `otp-email.html` для **Confirm signup**, **Magic link / OTP** та **Reset password**. У всіх трьох має бути `{{ .Token }}`, а не лише magic-link. Для цих шаблонів можна поставити теми «ВАТРА — підтвердження акаунта», «ВАТРА — код входу», «ВАТРА — відновлення доступу».
4. Перевірити Authentication → Providers → Email, Site URL та дозволені redirect URLs для `https://mykolakolisnyk.github.io/VATRA/auth.html`, включно з `?mode=new-password`.
5. Зробити тест на **власну** контрольовану пошту. Не тестувати масовою відправкою.

Без власного SMTP штатний Supabase обмежує листи тестовими адресами організації; реєстрація сторонніх користувачів через email не буде надійно доступна.

## SMS — обов'язкові налаштування адміністратора

1. Створити та підключити обліковий запис SMS-провайдера, який підтримується Supabase Auth (наприклад, Twilio, Vonage, MessageBird), із дозволеним надсиланням в Україну.
2. Authentication → Providers → Phone: увімкнути Phone, налаштувати SMS credentials і дозволені країни, вимагати підтвердження номера.
3. Authentication → SMS Templates: вставити текст `otp-sms.txt`, де код підставляється як `{{ .Code }}`.
4. Для імені відправника **VATRA** потрібна підтримка буквено-цифрового Sender ID цим оператором у відповідній країні та, за необхідності, реєстрація назви. Назва в тексті SMS сама по собі **не змінює** відправника.
5. Запустити один тест на власний номер у міжнародному форматі `+380XXXXXXXXX` і перевірити журнали провайдера.

## Захист та сумісність

- Діє обмеження повторного надсилання в інтерфейсі на 60 секунд; серверні rate limits і CAPTCHA необхідно також налаштувати в Supabase.
- Паролі існуючих акаунтів збережені: доступний вхід із паролем як резервний спосіб.
- Коди перевіряє Supabase, а не клієнтський JavaScript; без відповіді Auth-провайдера сторінка не підтверджується.
- Секрети SMTP/SMS, власний домен і тарифний провайдер не можуть бути налаштовані лише через файли GitHub. Поки їх не підключено, ніхто не повинен обіцяти фактичну доставку повідомлень.
