# Структура проєкту VATRA

Це карта **чинного** коду. Не створюйте нові `vatra-fix-2.css` чи `vatra-final-v3.css` поверх наявних стилів.

## Папки

| Каталог | Для чого потрібен |
| --- | --- |
| `assets/styles/` | Єдиний сайтівський CSS (`vatra.css`) та маніфест джерел (`manifest.json`) |
| `assets/scripts/navigation/` | Зміна маршрутів і повернення до початку сторінки |
| `assets/scripts/seo/` | Метадані поточної відкритої сторінки |
| `assets/scripts/search/` | Історія пошукових запитів |
| `assets/scripts/sidebar/` | Рекламні місця в бічній панелі (показ реклами вимкнено) |
| `assets/fonts/` | Локальні шрифти |
| `database/` | SQL-схема, функції та запити |
| `supabase/` | Серверні Edge Functions, email-шаблони, SQL-налаштування |
| `tools/` | Збирання, аудит і перевірки проєкту |
| `people/`, `communities/` | Автоматично створені публічні SEO-сторінки |
| `lang/` | Публічні мовні посадкові сторінки |
| `.github/workflows/` | Перевірки, публікація і оновлення SEO |

## Як працюють стилі

`index.html` завантажує **один** `assets/styles/vatra.css` замість 57 окремих CSS-запитів. Сторінки входу та реєстрації також завантажують **один** `assets/styles/vatra-auth.css` замість 10 файлів; їхні джерела в `assets/styles/auth-manifest.json`. Його створює `node tools/build-vatra-css.mjs` із вихідних CSS, перелічених **у правильному порядку** в `assets/styles/manifest.json`. Всі URL на локальні ресурси перераховуються відносно `assets/styles/`.

1. Знайдіть існуючий CSS-модуль у маніфесті. Змінюйте **саме його**, а не додатковий файл-перевизначення.
2. Прибирайте суперечливі або старі правила в тому самому компоненті.
3. Виконайте `node tools/build-vatra-css.mjs`. Комітьте змінений модуль і відповідний файл збірки (`assets/styles/vatra.css` або `assets/styles/vatra-auth.css`).
4. GitHub CI перевіряє, що збірка відповідає джерелам.

**Перехідний стан:** вихідні CSS ще лежать у корені для сумісності зі старими сторінками авторизації, тестами та модульними стилями. Їх не можна видаляти всі одразу. Нові стилі додавайте до існуючих компонентів, а не в окремі «полірувальні» файли.

## JavaScript

Поступово переносимо незалежні браузерні скрипти до `assets/scripts/<розділ>/`. У цьому етапі перенесено маршрутизацію прокрутки, SEO-метадані, історію пошуку та бічну рекламу; старі копії у корені вилучені. Основний `script.js`, `vatra-backend.js` і модулі із внутрішніми імпортами залишаються в корені до окремої перевіреної декомпозиції.

Не змінюйте URL JS-модулів без оновлення HTML, їхніх відносних імпортів та тестів.

## SEO і видимість

`tools/build-vatra-seo.mjs` створює сторінки профілів/спільнот та `sitemap.xml` **лише для записів, дозволених публічними правилами доступу**. GitHub Actions запускає генерацію за розкладом кожні 15 хвилин, а також вручну. Оновлення у браузері не означає миттєве оновлення пошукового індексу Google — індексація залежить від пошукової системи.

## Безпека

Приватні ключі Cloudflare, Supabase service-role, GitHub PAT і ключі SMTP/SMS не можна розміщувати в браузерному коді або комітити в GitHub. Перевірка CAPTCHA стає серверною лише після увімкнення відповідного провайдера у Supabase Auth.
