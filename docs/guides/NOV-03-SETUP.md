# ВАТРА — оновлення від 3 листопада 2026 року

## Що змінилося
- Форми входу й реєстрації: лінійні значки чоловічої та жіночої статі.
- Документи ВАТРИ: єдине вікно правил, політики конфіденційності й умов використання на сайті та в авторизації; компактні кнопки без синіх декоративних підкреслень.
- Профілі: коротка інформація + «Показати більше» для інших полів; без трьох громіздких розкладних блоків.
- Скарги: авторизований користувач може поскаржитися на допис або коментар через меню, із вибором причини. Заявки працюють через чинну систему модерації.
- Повідомлення: замість «Месенджер», індикатор непрочитаних діалогів, двостороннє серверне оновлення списку діалогів.
- Групові бесіди: створення з 1–19 друзями, список учасників, листування, окремі індикатори непрочитаного.
- Сповіщення про роль: компактна іконка замість розтягнутої овальної галочки.

## Що необхідно виконати у Supabase

**Увага:** нові файли SQL зберігаються у GitHub, але самі по собі **не виконуються** у робочій базі. У Supabase проєкту ВАТРИ відкрийте SQL Editor і послідовно застосуйте *повний вміст* цих файлів:

1. `database/reference/chats-social/vatra-chat-replies-and-unread.sql` — замінює старі правила шифрування для звичайних повідомлень і додає автоматичне оновлення вхідних індексів обох співрозмовників. Історичні зашифровані записи зберігаються.
2. `database/reference/security/vatra-rate-limits.sql` — серверне обмеження **10 нових дописів / 5 хвилин** і **20 нових коментарів / хвилину** для одного акаунта. Застосовується також до дописів спільнот.
3. `database/reference/chats-social/vatra-group-chats.sql` — приватні групові бесіди, права читання/запису, повідомлення, індекси і лічильники непрочитаного.

Ці SQL-файли **не вимикають RLS і не видаляють наявні повідомлення чи дописи**. Базова схема `database/reference/core/app-data-schema.sql` має бути налаштована раніше; без неї нові зміни не застосовуються. **Не перевиконуйте `app-data-schema.sql` після групової SQL-міграції без повторного запуску `vatra-group-chats.sql`**, бо стара схема видаляє й перевизначає політики доступу `app_data`.

Для збереження й обробки скарг в адмінпанелі, як і раніше, потрібна чинна `vatra-moderation-center.sql`. Оновлення цієї дати не повторює та не замінює її.

## Ручні перевірки після розгортання

1. Увійти в акаунт А та відкрити «Повідомлення». Надіслати текст акаунту Б, відповісти з Б, оновити обидві сторінки. Повторного `P0001` для звичайних повідомлень бути не повинно.
2. Увійшовши до Б, одержати повідомлення від А, але не відкривати діалог. Біля «Повідомлення» має з’явитися кількість непрочитаних діалогів; після відкриття лічильник зменшується.
3. Створити групову бесіду з двома друзями. Перевірити написання та читання всіх трьох користувачів, сповіщення про нові повідомлення, а також що четвертий сторонній акаунт не може читати чужий чат.
4. Надіслати повторно 11 нових дописів за п’ять хвилин або 21 коментар за хвилину: останній запис має блокувати сервер із коректним повідомленням без збереження.
5. Натиснути «Поскаржитися» на чужому дописі/коментарі, вибрати «Образи або переслідування» і перевірити заявку в модераційній адмінпанелі.
6. Перевірити документи та «Показати більше» на ПК і телефоні; перевірити сповіщення «Вам надано роль у ВАТРІ» у випадаючому меню та на окремій сторінці.

## Статус перевірок

GitHub Actions перевіряє синтаксис JavaScript і наявність модулів. Але CI-перевірка **не дорівнює** тесту реальної роботи з Supabase. До застосування міграцій і перевірки двома-трьома акаунтами не можна вважати групові чати, обмеження частоти або виправлення `P0001` перевіреними в живій базі.
