# ВАТРА — Firebase social web app

Це клієнтський вебзастосунок, підключений до Firebase-проєкту `vatra-a4fb0`. Це вже не статичний макет: основні дії викликають Firebase Authentication, Realtime Database та Cloud Storage.

## Реалізовано в коді

- Реєстрація, вхід, вихід та відновлення пароля через Email/Password.
- Окрема адаптивна форма авторизації: перевірка email, підтвердження пароля під час реєстрації, показ/приховування пароля, зрозумілі повідомлення про помилки та індикатор виконання.
- Профіль: ім'я, псевдонім, біографія, фото профілю.
- Стрічка: текстові дописи, фото, лайки, коментарі, збереження, видалення власних дописів.
- Підписки та пошук зареєстрованих користувачів.
- Приватні чати між користувачами з оновленням повідомлень у реальному часі.
- Спільноти: створення, вступ/вихід і публікації для учасників.
- Короткі відео: завантаження та перегляд.
- Адаптивний інтерфейс для телефонів і комп'ютерів.

## Обов'язкове одноразове налаштування Firebase

Код не може самостійно змінювати налаштування в консолі Firebase. У проєкті `vatra-a4fb0` потрібно:

1. Відкрити **Authentication → Sign-in method** і ввімкнути **Email/Password**.
2. У **Realtime Database → Rules** опублікувати вміст `database.rules.json`.
3. Створити/активувати **Storage**, якщо його ще немає, і опублікувати `storage.rules` у Storage → Rules. Умови тарифного плану Firebase Storage можуть вимагати платіжний план.
4. Для локального тестування переконатися, що `localhost` є в Authentication → Settings → Authorized domains.

**Не використовуй відкриті правила на кшталт `".read": true` або `".write": true`.** Файли правил у цьому пакеті обмежують доступ за користувачем/учасником.

## Як відкрити локально без публікації на хостингу

Оскільки `script.js` використовує Firebase ES-модулі, відкриття `index.html` через подвійний клік (`file://`) зазвичай не працює. Це обмеження браузера, не хостинг. Для локальної перевірки:

1. Відкрий папку у Visual Studio Code.
2. Запусти розширення **Live Server** для `index.html`.
3. Відкрий адресу `http://127.0.0.1:5500` або адресу, яку покаже Live Server.

Це лише локальний сервер на твоєму комп'ютері — сайт не публікується в інтернеті.

## Перевірка

- Синтаксис `script.js` перевірено через `node --check`.
- JSON правил Realtime Database перевірено на коректний синтаксис.
- Реальні операції Firebase не можна підтвердити з боку автора файлів без запуску в твоєму Firebase-проєкті. Якщо Firebase відхилить операцію, інтерфейс покаже повідомлення з помилкою.

## Файли

- `index.html` — інтерфейс.
- `style.css` — стилі й адаптивність.
- `script.js` — логіка Firebase.
- `database.rules.json` — правила Realtime Database.
- `storage.rules` — правила Cloud Storage.


## Оновлення: окрема авторизація та профілі
- `auth.html` — окрема сторінка входу, реєстрації та відновлення пароля.
- `auth.js` / `auth.css` — логіка й оформлення форми авторизації.
- Неавторизований відвідувач переходить на `auth.html`; після входу повертається до `index.html`.
- Стрічка показує власні дописи, дописи людей, на яких користувач підписаний, та публікації спільнот, до яких він приєднався. Якщо дописів немає — показується порожня стрічка.
- Додані запити в друзі, прийняття/відхилення запитів і перегляд публічного профілю з пошуку.
- У Firebase Realtime Database потрібно опублікувати оновлений `database.rules.json`.
- Запускай папку через VS Code Live Server або інший локальний HTTP-сервер, не подвійним кліком по HTML.

**Статус перевірки:** перевірено синтаксис JS, валідність JSON правил і базову структуру файлів. Реальну роботу Auth/Realtime Database/Storage у твоєму Firebase-проєкті потрібно підтвердити браузерним тестом після налаштування Firebase; повну перевірку всіх сценаріїв не можна вважати завершеною до цього тесту.
