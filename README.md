# VATRA

VATRA — українська соціальна платформа, яку розробляє один розробник. Поточний сайт містить авторизацію, реєстрацію, відновлення пароля, особисту сторінку, підтвердження пошти, документи та першу версію **Стрічки**. Текстові публікації — перша соціальна функція; профілі, друзі, месенджер, спільноти, відео, кліпи, збережене та налаштування розвиватимуться наступними етапами.

**Один HTML-файл на сторінку.** Немає окремих папок `ua/` та `en/`, дубльованих HTML чи версій `v2/v3`. Файли `email-templates/` — це саме шаблони листів Supabase, не публічні сторінки сайту.

- На головній сторінці обидві колонки однакової ширини (1 : 1) і вертикально центрують свій вміст; на вузьких екранах форма входу й композиція логотипа переходять у вертикальний порядок. Під логотипом опис VATRA вирівняний з лівим краєм футера, обмежений 69ch і має адаптивний розмір 14–15 px для стабільного перенесення рядків. Логотип зберігає плавну анімацію, коло та 8 кольорових SVG-іконок — попередні розміри. Для бізнес-іконки використовується коротка назва «Бізнес» / «Business». Підказки іконок обирають напрямок відповідно до доступного місця. Поля входу й реєстрації мають спільну анімацію та шрифт Onest.

- У `lang.js` збережений вибір мови має перевірятися лише після оголошення `validLanguage`, інакше модальне вікно взагалі не ініціалізується. Три складові кнопки (прапорець SVG, назва і стрілка) присутні в HTML як резервна розмітка, а після завантаження JS відображається повний вибір із 36 мовами.

- `assets/js/errors.js` не виводить декоративних написів у DevTools. Він показує знизу ліворуч червоні повідомлення **VATRA · Помилка** для `console.error`, необроблених JavaScript-помилок і Promise, а також окремі жовто-бурштинові **VATRA · Попередження** для `console.warn`. Картки автоматично зникають приблизно через 5,4 секунди; приватні дані маскуються. Помилки заповнення форм залишаються під полями. Внутрішні браузерні Issues/Warnings, які не передаються в `console.warn`, сайт з міркувань доступу до браузера не перехоплює.
- Поле пошуку мов має унікальні `id` і `name` (щоб не виникало попередження DevTools щодо автозаповнення). Скрипти й стилі підключаються за сталими URL без параметрів `?v=`. Service Worker працює за принципом network-first, а його внутрішній ключ кешу оновлюється тільки для міграції офлайн-ресурсів. Після публікації CDN/браузер може короткочасно віддавати старі файли; для негайної перевірки оновіть сторінку без кешу.
- На основній сторінці використовується **стандартний скролбар браузера**. Фірмовий скролбар застосовується лише всередині списків вибору дня/місяця/року, статі й прокручуваного діалогу CAPTCHA; у вікні вибору мови — окремий фірмовий інтерактивний повзунок. Глобальні `*::-webkit-scrollbar` та `*{scrollbar-width:...}` не використовуються.
- Підказки реєстрації ведуть до розділу «Навіщо потрібні Ваші дані» у Політиці конфіденційності. Там окремо описано призначення email і необов’язковість вибору статі.


## Мова інтерфейсу

- Українська — мова HTML за замовчуванням; англійська завантажується з `assets/i18n/en.json`. В `assets/i18n/uk.json` зберігаються українські відповідники.
- `assets/js/lang.js` визначає мову за збереженим вибором (`localStorage["vatra-language"]` і резервний cookie `vatra-language` зі строком дії до 365 днів); коли вибору немає — за мовою браузера. Перемикач зберігає вибір і перезавантажує **цю саму URL-адресу**, без мовних папок. Старі посилання `/ua/` і `/en/` більше не перезаписують уже вибрану мову.
- Якщо браузер працює в приватному режимі або очищає **всі** дані сайту при виході (і cookie, і localStorage), зберегти вибір між запусками неможливо: потрібно дозволити збереження даних для `mykolakolisnyk.github.io`.

- У кожного текстового елемента зберігається окремий клас. `data-i18n="n…"` зіставляє елемент із перекладом у розділі `__pages.<сторінка>.nodes` обох JSON. Метадані сторінок зберігаються в `__pages.<сторінка>.meta`.
- Службові повідомлення автентифікації перекладаються за попередніми словниковими ключами `en.json`.
- Прапорець Великої Британії тепер має точні SVG-контури, а стрілка перемикання мови — SVG замість текстового символу; решта прапорців залишаються векторними із джерел `assets/flags/`.
- У вікні вибору показані всі **36 мов** із пошуком і прапорцями. **Українська** та **English** працюють; решта мають позначку «У розробці» й недоступні для вибору. Для активних мов прапорці вбудовані як SVG, для інших використовуються спрайти `assets/flags/`.
- Старі посилання `/VATRA/ua/...` і `/VATRA/en/...` із закладок та листів перенаправляються з кореневого `404.html` на відповідні нові сторінки. Невідомі URL залишаються помилкою 404.

Головна: https://mykolakolisnyk.github.io/VATRA/

Не використовувати `hreflang` для двох мов одного URL: інтерфейс перекладається клієнтом на одній адресі. Для багатомовного SEO у майбутньому можна повернути окремі URL мов, але не дубльовані шаблони.

`assets/fonts/Onest-Variable.ttf` — локальний шрифт із ліцензією `assets/fonts/OFL.txt`. Логотипи — тільки з `assets/logo/`. Вкладки та посилання використовують favicon, Open Graph і PWA manifest. Вигляд плитки швидкого доступу Opera також залежить від кешу браузера.

## Доступ до сайту та робота без інтернету

- `assets/js/host.js` дозволяє завантажувати робочий інтерфейс лише через офіційний HTTPS-хост `https://mykolakolisnyk.github.io/VATRA/`. Для локального `file://`, `localhost` та інших адрес відображається повідомлення з посиланням на офіційний сайт.
- Це перевірка на клієнті, **не DRM і не гарантія від копіювання**: HTML/CSS/JS можна завантажити, а локальну перевірку — видалити або змінити. Права на приватні дані й дії користувача мають перевірятися на сервері через Supabase Auth, RLS та інші серверні засоби.
- На `offline.html` логотип вбудований SVG-вектором із `assets/logo/vatra-logo.svg`, а кореневий `favicon.svg` відповідає `assets/logo/vatra-app-icon.svg`. Іконка відсутнього Wi-Fi теж вбудована вектором.
- Service worker кешує офлайн-сторінку, обидва JSON-переклади й необхідні ресурси. Для оновлення офлайн-дизайну спершу відкрийте сайт з інтернетом, щоб браузер встановив оновлений worker.

## Supabase: оновити URL Configuration

**Вручну** відкрийте Supabase Dashboard → Authentication → URL Configuration.

- **Site URL:** `https://mykolakolisnyk.github.io/VATRA/`
- **Redirect URLs:** `https://mykolakolisnyk.github.io/VATRA/account.html` і `https://mykolakolisnyk.github.io/VATRA/reset.html`.
- Старі адреси `/ua/account.html`, `/en/account.html`, `/ua/reset.html`, `/en/reset.html` більше не генеруються; після тестування їх можна прибрати з дозволеного списку.
- **Дії:** перевірити реєстрацію та лист підтвердження, вхід, код відновлення й захищене посилання, зміну пароля та вихід.

`assets/js/auth.js` використовує тільки публічний ключ Supabase і зберігає `preferred_locale` (`uk` або `en`) у метаданих під час реєстрації. Вхід і реєстрація **лише через email і пароль**; телефон/SMS не додавати. Зміна мови після створення акаунта не оновлює автоматично вже збережений `preferred_locale` для листів.

Відновлення: `resetPasswordForEmail` → email із одноразовим кодом → `verifyOtp({type:"recovery"})` у **тимчасовій незбереженій сесії** → `updateUser({password})` → завершення тимчасової сесії → **вхід із новим паролем**. Якщо користувач закриває відновлення після перевірки коду, звичайний вхід автоматично не відкривається. Захищені посилання підтримуються. Не вигадувати власні OTP-коди: використовувати Supabase.

Рекомендована політика: пароль **12–128 символів**, малі й великі латинські літери, цифра та спеціальний символ; Email OTP **6–10 цифр** (рекомендовано налаштувати **8** на сервері), строк **900 секунд**. Налаштування серверної політики зберігати в Supabase Dashboard. Для публічного запуску на **Supabase Pro** увімкнути перевірку відомих скомпрометованих паролів та перевірити налаштування Auth. Поточний тариф розробки не змінювати без окремої команди.

## Cloudflare Turnstile

Публічний **Site Key** уже є в `assets/js/captcha.js`. Секретний ключ зберігати **тільки** у Supabase Authentication → Attack Protection; не додавати його в GitHub або HTML. CAPTCHA показується в модальному вікні після натискання кнопки входу, реєстрації та надсилання листа. Після отримання `captchaToken` запит надсилається в Supabase. Повторні спроби потребують нового токена.

Використовуйте `mykolakolisnyk.github.io` як дозволений hostname Cloudflare. У разі розходження ключів спочатку виправляйте налаштування, а не відключайте перевірку в браузерному коді.

## Листи

`email-templates/` містить вісім шаблонів Supabase (реєстрація, запрошення, магічний лінк, зміна адреси, відновлення, повторна автентифікація, сповіщення про зміну пароля та адреси). У всіх восьми шаблонах логотип — публічний PNG `https://mykolakolisnyk.github.io/VATRA/assets/logo/vatra-logo.png`, що відповідає актуальному файлу `assets/logo/vatra-logo.png`. Вони підтримують українську й англійську через `{{ .Data.preferred_locale }}`.

**Фінальний реліз планується на Supabase Pro.** GitHub не синхронізує шаблони автоматично з Dashboard: `Body → Source` та `Subject` потрібно вносити окремо. До запуску налаштувати надійний SMTP, SPF, DKIM і DMARC та перевірити доставку листів.

## Стрічка (перший етап)

- Назва розділу **«Стрічка»** / **Feed**; не «Стрічка новин». Після успішного входу або підтвердженої реєстрації `auth.js` відкриває `/VATRA/feed`; сторінка `/VATRA/verify` обробляє одноразові підтверджувальні посилання Supabase і після перевірки переводить у Стрічку. Старі `/VATRA/account.html` обробляються через 404-перенаправлення.
- `feed.html`, `profile.html`, `verify.html`, `assets/css/feed.css`, `assets/js/feed.js`, `assets/js/profile.js` — файли нового модуля. В URL вони відкриваються як `/feed`, `/id<vatra_id>`, `/verify`, без `.html`. Файл `profile.html` є технічною точкою входу для адрес користувачів. Тексти двох доступних мов зберігаються в `uk.json` і `en.json`. На мобільних навігація змінює компонування, а не обрізає публікації.
- Публікації поки **лише текстові**, від 1 до 2000 символів, найновіші спочатку. Користувач може створити й видалити власний допис. Показ чужих дописів не розкриває чужий email чи службовий Auth UUID; замість них відображається публічний VATRA ID. Профіль за VATRA ID показує публікації власника, не розкриваючи приватні поля; вкладення розроблятимуться окремо.
- У Supabase додана таблиця `public.feed_posts`. Увімкнено RLS: читання лише для авторизованих, вставлення від власного `auth.uid()` і пов’язаного з ним VATRA ID, видалення лише своїх дописів. Ролі `anon` не надано читання; `authenticated` не має права `SELECT` для `author_id`.
- Навігація містить узгоджені розділи: Стрічка, Моя сторінка, Друзі, Месенджер, Спільноти, Відео, Кліпи, Маркетплейс, Збережене, Налаштування. У першій версії Стрічка працює, «Моя сторінка» веде на `/VATRA/id<vatra_id>`; автори дописів відкриваються за власними ID, решта пунктів ще недоступні.
- Перед відкриттям повноцінного публічного сервісу потрібні правила модерації, запобігання спаму, завершення функцій профілю, юридичне оновлення політик і тестування реальної доставки/авторизації. Поточні браузерні тести використовують підставні дані, не створюють користувачів чи дописів у продакшні.

## Захист даних та поточний стан

- `public.accounts` зберігає дані акаунтів; публічний довідник `public.vatra_directory` відкриває тільки VATRA ID, без приватних полів. Доступ має контролюватися RLS.
- Для показу VATRA ID клієнту потрібен мінімальний доступ `GRANT SELECT (user_id, vatra_id) ON public.accounts TO authenticated;` — цей доступ застосовано в Supabase 8 листопада 2026 року. Політика RLS `Read own VATRA ID` додатково дозволяє читати лише власний запис. Анонімного доступу до `accounts` немає.
- Таблиця `private.vatra_id_counter` зараз має вимкнений RLS (попередження аудиту). За перевіркою привілеїв `anon` і `authenticated` не мають доступу до таблиці та схеми `private`; не вмикати RLS автоматично без аналізу функції видачі ID.
- В Supabase Auth аудит показує вимкнений захист від відомих скомпрометованих паролів. Увімкнути в Dashboard, якщо функція доступна для тарифу.
- Постійний VATRA ID показується в профілі, а канонічна адреса має вигляд `/VATRA/id123456789`. GitHub Pages обробляє прямі переходи через `404.html`, який завантажує статичний документ профілю без зміни `/VATRA/idN` в адресному рядку. Інші користувачі бачать лише публічний ID та дописи; приватні дані Supabase Auth залишаються прихованими.
- Кореневий `404.html` — сторінка **помилки**, а не профіль. Для невідомих адрес GitHub Pages використовує саме її; для старих локалізованих посилань є обмежена переадресація.
- `sw.js` кешує одну `offline.html`, `lang.js`, обидва JSON-словники, логотип та шрифт після першого онлайн-візиту. `assets/js/network.js` показує попередження про втрату зв’язку.
- Публічні документи VATRA — робочі; перед запуском повноцінної соцмережі їх потрібно юридично перевірити та забезпечити актуальні процедури роботи з персональними даними.

### Спільноти VATRA та постійні Club ID (листопад 2026)

- Розділ `/VATRA/communities` відкриває каталог і базове створення спільнот. Для кожної існуючої спільноти є канонічна адреса `/VATRA/clubN` (наприклад, `/VATRA/club1`). Прямий перехід на `/clubN` обробляється GitHub Pages через `404.html`, який завантажує документ спільноти без проміжної адреси `club.html`.
- У Supabase `public.communities` окремий `club_id bigint generated always as identity`. Його послідовність починається з 1, відокремлена від `private.vatra_id_counter` (який призначає VATRA ID користувачів), не скидається від видалення спільнот і не видає видалені номери повторно. Номери призначає БД, не JavaScript.
- Застосовано RLS: каталог читається публічно, лише авторизований користувач може створити спільноту від власного імені. Через Data API відкриті лише `club_id`, назва, опис і дата створення; внутрішній `owner_id` прихований від SELECT. Видалення, редагування, модерація, учасники, обкладинки та публікації спільнот поки не реалізовані.
- `communities.html`, `club.html`, `assets/js/communities.js`, `assets/css/communities.css` — єдині файли модуля, без дубльованих v2 або мовних директорій. Підтримка української й англійської; усі текстові поля виводяться як текст (без небезпечного HTML).


### Єдиний екран завантаження VATRA

- Один спільний CSS-компонент `.vatra-auth-loading` і однакові розміри смужки для входу, реєстрації, перевірки пошти, відновлення пароля, стрічки, профілів та спільнот. Смужка є **невизначеним індикатором очікування**, а не вигаданим відсотком завантаження. Штучні затримки для вигляду відсутні.
- На сторінках авторизації індикатор приховується після завершення ініціалізації й перевірки сесії; у стрічці, профілях і спільнотах — лише після першого запиту до бази й відображення результату, порожнього стану або помилки. На статичних сторінках без асинхронних даних індикатор не створюється штучно.
- У разі критичної помилки під час початкового завантаження соціальних розділів показується повідомлення й кнопка повторної спроби, а анімація очікування припиняється.
