# VATRA

VATRA — соціальна платформа. Поточний репозиторій містить авторизацію, реєстрацію, відновлення пароля та інформаційні сторінки.

## Структура

- `index.html` — мовний маршрутизатор: відкриває /ua/ або /en/ за збереженим вибором чи мовою браузера; основна мова бренду — українська.
- У корені залишені лише технічні файли: `index.html` (вибір мови), `404.html` (технічне перенаправлення GitHub Pages на `/ua/404.html` чи `/en/404.html`), `sitemap.xml`, `sw.js`, `favicon.svg` і `site.webmanifest`. Дубльовані кореневі HTML-перенаправлення видалені.
- `ua/` — українські сторінки VATRA; єдина форма входу розташована в `ua/index.html` і доступна за `/VATRA/ua/`.
- `en/` — англійські сторінки VATRA; єдина форма входу доступна за `/VATRA/en/`.
- У кожній мовній папці лише одна форма входу — `index.html`; файли `ua/auth.html`, `en/auth.html` та кореневий `auth.html` видалено.
- `ua/offline.html` і `en/offline.html` — самодостатні офлайн-сторінки відповідною мовою.
- `sw.js` — Service Worker, що кешує офлайн-сторінки та видає їх при збоях мережі після початкового онлайн-візиту.
- `assets/js/network.js` — компактне попередження про втрату з'єднання на відкритій сторінці.
- `assets/i18n/en.json` — українсько-англійські відповідники інтерфейсу та повідомлень
- `assets/js/lang.js` — перемикач мови і каталог 36 мов (працюють українська й англійська)
- `assets/flags/` — локальні SVG-прапори з open-source flag-icons (ліцензія MIT у LICENSE.txt)
- `assets/css/auth.css` — локальний шрифт Onest та спільні стилі авторизації
- `assets/js/auth.js` — логіка Supabase Auth
- `assets/logo/` — завантажені офіційні логотипи VATRA у SVG та PNG. Використовувати тільки їх, не перемальовувати.

## Налаштування Supabase

У проєкті Supabase VATRA встановіть **Site URL** `https://mykolakolisnyk.github.io/VATRA/` і додайте дозволені Redirect URLs:
- `https://mykolakolisnyk.github.io/VATRA/ua/account.html`
- `https://mykolakolisnyk.github.io/VATRA/en/account.html`
- `https://mykolakolisnyk.github.io/VATRA/ua/reset.html`
- `https://mykolakolisnyk.github.io/VATRA/en/reset.html`

Підтвердження email та відновлення пароля вимагають налаштованого надсилання email. Для реального публічного запуску підключіть SMTP-провайдера; стандартний поштовий сервіс Supabase має обмеження. Не додавайте до репозиторію секретні ключі. У клієнті використовується лише публічний publishable key.

Телефонна авторизація вимкнена за рішенням власника VATRA; не додавати SMS/телефон у форми та email-шаблони.

## Шрифт Onest

- `assets/fonts/Onest-Variable.ttf` — оригінальний змінний шрифт Onest (100–900), завантажується **тільки з цього репозиторію**.
- `assets/fonts/OFL.txt` — текст відкритої ліцензії SIL Open Font License 1.1.
- У файлі `assets/css/auth.css` шрифт підключений локальним `@font-face`. Зовнішній Google Fonts не використовується.

## Email-підтвердження та відновлення пароля

- `/ua/forgot.html` і `/en/forgot.html` надсилають запит на відновлення через Supabase Auth (`resetPasswordForEmail`) з локалізованим `redirectTo`.
- `/ua/reset.html` та `/en/reset.html` приймають email + одноразовий код (6–8 цифр) через `verifyOtp({ email, token, type: "recovery" })`. Після перевірки відкривають форму нового пароля; відновлення за захищеним посиланням також підтримується.
- Під час реєстрації зберігається `preferred_locale` — `uk` або `en`, аби шаблони листів могли вибирати потрібну мову.
- Готові HTML-шаблони: `email-templates/recovery.html`, `confirmation.html`, `magic-link.html`, `reauthentication.html`.
- **Hosted Supabase не підтягує HTML-файли з GitHub автоматично!** Для активування адміністратор має в **Authentication → Emails → Templates** вручну вставити вміст відповідного файлу, указати тему та зберегти. Наразі готовність файлів у репозиторії не означає, що листи вже надсилаються українською.
- Підключити лише email; SMS/телефон не використовувати. У **Authentication → URL Configuration** дозволити обидва локалізовані адреси `account.html` і `reset.html`. Старі кореневі посилання вже не працюють.
- Для існуючих користувачів без `preferred_locale` шаблон показує українську як основну мову. Після нових реєстрацій мову визначає поле метаданих; зміна мови інтерфейсу не обов'язково змінює цю метадані автоматично.

## Іконки й мініатюри

- `favicon.svg` — коренева іконка VATRA, скопійована з офіційного `assets/logo/vatra-app-icon.svg`.
- `site.webmanifest` — ім'я VATRA та офіційна іконка PNG для підтримуваних браузерів і встановлення.
- У сторінок є `rel=icon` (SVG/PNG), `apple-touch-icon`, Open Graph та інші метатеги. Opera Speed Dial може брати власний кешований знімок: метатеги **не гарантують** вигляду плитки швидкого доступу.

## Пошук та індексація

- `ua/index.html` і `en/index.html` мають окремі canonical, Open Graph, Twitter Card та структуровані дані. Кореневий `index.html` обирає мовну версію.
- `sitemap.xml` містить українські та англійські адреси п'яти публічних сторінок з взаємними hreflang-посиланнями. Її можна додати до Google Search Console.
- Сторінки входу, реєстрації, відновлення та акаунта мають `noindex`. Документи й головна сторінка — публічні.
- Відкритий запуск, постійна адреса сайту та політики потребуватимуть оновлення метаданих.

## Сторінка помилки, акаунт та поля входу

- Після входу користувач переходить до `/VATRA/ua/account.html` або `/VATRA/en/account.html`; там відображається його постійний VATRA ID. Окремі сторінки користувачів ще не створено.
- Публічний довідник `public.vatra_directory` містить **лише** `vatra_id` без email, дати народження, UID та інших особистих даних. RLS дозволяє читання тільки цього публічного номера. Новий рядок створюється разом із `public.accounts` одним тригером.
- `/ua/404.html` та `/en/404.html` містять **повноцінну сторінку помилки** VATRA з логотипом, кнопкою на головну, футером і вибором мови. Кореневий `404.html` потрібен лише GitHub Pages, щоб при невідомому маршруті перенаправити на відповідний мовний файл. Він не завантажує Supabase, профілі чи приватні дані. Публічні `/idN` не реалізовані.
- `account.html` — екран акаунта з виходом; VATRA ID показано текстом, без посилання на відсутню сторінку.
- Плаваючі підписи для всіх текстових форм налаштовано у **наявному** `assets/css/auth.css` за станом фокуса та введеного значення. Окремі файли `*-fix.css` не створюються.
- Навколо логотипа V три підписи рухаються зовнішньою орбітою та чотири SVG-іконки — внутрішньою, у протилежному напрямку.
- Вікно вибору мов має власний видимий повзунок VATRA (синьо-фіолетовий), підтримує його перетягування, колесо миші, клавіатуру й дотик.

## VATRA ID

- Публічний ідентифікатор VATRA ID — унікальний постійний числовий номер, який видає транзакційний лічильник PostgreSQL після створення запису в auth.users.
- Внутрішній UUID системи авторизації залишається первинним ключем для безпечних зв'язків і перевірки прав; він не є номером VATRA ID, який бачать користувачі.
- Таблиця `public.accounts` містить `user_id`, `vatra_id` (постійний публічний номер) і `created_at`.
- Тригер `on_vatra_auth_user_created` викликає `private.assign_vatra_id`, який блокує рядок `private.vatra_id_counter` в одній транзакції із записом нового акаунта. Помилки реєстрації не витрачають номери. Видалення акаунтів може залишати пропуски; номери не повторно видаються.
- Таблиця має RLS: користувач може прочитати лише власний VATRA ID. Видача номера відбувається на сервері без можливості вибрати його з браузера.
- При реєстрації користувач бачить пояснення, що номер буде надано автоматично. В акаунті він відображається як `VATRA ID 1` тощо.
- Потрібно протестувати повний сценарій створення акаунта, підтвердження email та відображення номера після реальної реєстрації.

## Мовна система

- Українська й англійська працюють за чистими адресами `/VATRA/ua/` і `/VATRA/en/`. Корінь `/VATRA/` вибирає мову за збереженим вибором чи мовою браузера. Старий `locale=uk_UA/en_US` розпізнається лише при відкритті старих посилань, після чого видаляється. Інші мови браузера поки відкривають англійську.
- Внутрішні посилання не містять `locale`; `index.html` нормалізується до адреси мовної папки. Відвідування явного `/ua/` чи `/en/` також запам’ятовує вибрану мову.
- Публічні персональні адреси `/VATRA/idN` ще не запущено; до їх появи `/VATRA/idN` правильно відображає сторінку помилки 404.
- Вибір зберігається у браузері, тож переходи між розділами зберігають мову.
- Інші 34 мови доступні в каталозі зі статусом «У розробці», але їхній переклад і перемикання не ввімкнено.
- Усі 36 прапорів — векторні SVG, узяті з MIT-ліцензованого репозиторію lipis/flag-icons: https://github.com/lipis/flag-icons. Текст ліцензії включено в `assets/flags/LICENSE.txt`.
- При редагуванні українського тексту оновлюйте відповідну англійську сторінку та переклад у `assets/i18n/en.json`; не створюйте дубльованих CSS override-файлів.

## Форми, валідація та офлайн

- Плаваючий підпис — один невиокремлюваний текст всередині поля: при фокусі/значенні/автозаповненні він анімовано підіймається й зменшується. Дубльований placeholder з інпутів прибирається; при помилках підпис не зміщується через додаткову висоту пояснення.
- `assets/js/auth.js` виконує перевірку пустих, некоректних та невідповідних полів: конкретна помилка відображається під полем і позначає його через `aria-invalid`.
- Під час створення пароля показуються вимоги; у формі входу зайвої підказки під паролем немає. Менеджери паролів Opera/Chrome показують власні браузерні підказки, не VATRA.
- `assets/js/network.js` показує стан втрати інтернету, не скидаючи введених даних у відкритій формі.
- Після першого візиту онлайн `sw.js` кешує /ua/offline.html та /en/offline.html. Якщо користувач офлайн відкриває іншу сторінку, показується відповідна кешована офлайн-сторінка. При першому візиті без інтернету Service Worker іще не встановлений, тому браузер показує своє стандартне повідомлення.

## Адаптивність та хостинг

- Сторінки розраховані на ПК, планшети та смартфони. SVG-логотипи отримують адаптивну висоту, щоб шапка не розтягувалася.
- `assets/js/host.js` перевіряє офіційне HTTPS-розміщення `mykolakolisnyk.github.io/VATRA/`; звичайний запуск з `file://` і localhost блокується.
- **Це лише клієнтське обмеження, а не захист авторського коду:** скопійований HTML/JS можна змінити. Справжні обмеження даних, платіжних операцій і платних можливостей мають бути на сервері, з автентифікацією та перевіркою прав.


## Листи Supabase і безпека пошти

- Вхід і реєстрація виконуються **лише за електронною поштою** (email+пароль). Телефон, SMS і номер для входу не додаються.
- У папці `email-templates/` лежать **шість відповідних шаблонів Supabase** та `README.md` із предметами листів, змінними й інструкцією вставлення в Dashboard.
- GitHub-публікація **не змінює автоматично** листи продакшн Supabase: застосувати `Body → Source` і `Subject` у Dashboard потрібно окремо.
- Шаблони вибирають українську чи англійську за `{{ .Data.preferred_locale }}`, яку форма реєстрації зберігає в метаданих. За відсутності метаданих використовується українська. Налаштування мови сайту після створення акаунта саме собою не змінює вже записану метамову користувача.
- Відновлення пароля використовує **стандартний цифровий OTP** Supabase `{{ .Token }}` та захищені посилання `{{ .ConfirmationURL }}`. Власних буквено-цифрових кодів не генеруємо.
