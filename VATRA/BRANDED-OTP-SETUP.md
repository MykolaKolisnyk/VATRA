# Додатковий варіант: власні коди підтвердження ВАТРИ

> **АРХІВНИЙ ДОКУМЕНТ — НЕ ВИКОРИСТОВУВАТИ ДЛЯ ПОТОЧНОЇ ВЕРСІЇ.** Поточна ВАТРА працює за паролем без кодів підтвердження під час входу чи реєстрації. У Supabase потрібно вимкнути `Confirm email` і `Confirm phone`. Цей файл описує лише необов’язкову майбутню альтернативу з власним OTP, яку не розгорнуто. Актуальні налаштування: `SUPABASE-AUTH-SETUP.md`.

Це серверний модуль для власних кодів ВАТРИ. Він не активований і сам по собі не забезпечує доставку. Не розгортайте його для поточної реєстрації, доки не вирішено перейти з OTP Supabase на власну серверну реалізацію.

## Що дає
- Восьмисимвольний код із великих літер і цифр для email та SMS.
- Термін дії 10 хвилин, одноразове використання, максимум 5 спроб і ліміти повторного надсилання.
- Брендований лист ВАТРИ та SMS-текст із назвою ВАТРА.
- Секрети провайдерів залишаються на сервері.

## Підключення в Supabase
1. Виконайте `vatra-otp-schema.sql` у SQL Editor.
2. У Supabase CLI увійдіть у потрібний проєкт, відкрийте каталог `VATRA OLD` і виконайте `supabase functions deploy vatra-otp --project-ref rjasunoawrxvetwadylh`. Файл `supabase/config.toml` вимикає JWT-перевірку лише для цього публічного реєстраційного endpoint.
3. Функція має `verify_jwt = false`, оскільки реєстрація доступна до входу; захист забезпечують короткий термін коду, ліміти на контакт/IP і серверна перевірка. З каталогу `VATRA OLD` задай секрети командою `supabase secrets set --project-ref rjasunoawrxvetwadylh VATRA_OTP_PEPPER="<довгий випадковий секрет>" RESEND_API_KEY="<ключ Resend>" VATRA_EMAIL_FROM="ВАТРА <auth@your-verified-domain>" TWILIO_ACCOUNT_SID="<SID>" TWILIO_AUTH_TOKEN="<токен>" TWILIO_FROM_NUMBER="<номер Twilio>"`. Замініть усі значення в кутових дужках на справжні; не публікуйте їх у GitHub і не вставляйте в браузер. `SUPABASE_URL` і `SUPABASE_SERVICE_ROLE_KEY` мають бути доступні Edge Function у середовищі Supabase.
4. Для email домен/адреса відправника мають бути підтверджені у Resend. Для SMS потрібен активний Twilio-відправник і доступність доставки в Україну; короткий брендований sender ID залежить від країни та провайдера. У тексті SMS вже є назва «ВАТРА», але номер відправника визначає Twilio, а не вебсайт.
5. Цей альтернативний потік **не підключений** до поточного `auth.js`. Для його активації потрібні розгортання Edge Function, секрети та окрема зміна клієнтського коду. Поточний код ВАТРИ використовує `signUpWithPassword`/`signInWithPassword`: вхід і реєстрація — за паролем без коду. У Supabase вимкни `Confirm email` і `Confirm phone`, як описано в `SUPABASE-AUTH-SETUP.md`.

## Важливе обмеження
Саме створення функції й таблиці не вмикає новий OTP у живій ВАТРІ. Потрібні секрети провайдерів, розгортання функції та підключення клієнтського коду. Для поточного режиму Supabase OTP слід налаштовувати лише за `SUPABASE-AUTH-SETUP.md`. Не вимикайте RLS і не розміщуйте service-role key у frontend.


## Як саме бачить код користувач

- **Email:** лист надсилає Edge Function через Resend, із темою та HTML-шаблоном ВАТРИ. У VATRA_EMAIL_FROM потрібно вказати відправника ВАТРИ на домені, який підтверджено в Resend; сам напис у шаблоні не може замінити перевірку домену.
- **SMS:** текст містить «ВАТРА» і випадковий восьмисимвольний код із літер та цифр. Номер/ім’я відправника SMS визначає Twilio та правила доставки в країні отримувача.
- **Не працюватиме лише від завантаження файлів у GitHub:** функцію треба розгорнути в Supabase і додати секрети провайдерів. Якщо їх немає, код безпечно покаже повідомлення, що доставка не налаштована; він не перемикається на код Supabase за замовчуванням.
