# ВАТРА: унікальні @псевдоніми та офіційні галочки

Використовується **Supabase**, не Firebase. Галочка зберігається за незмінним **UUID користувача**, а @псевдонім використовується лише для пошуку під час видачі або відкликання.

## 1. Міграція
У Supabase → SQL Editor (проєкт ВАТРИ) переконайтеся, що вже застосовано `VATRA/app-data-schema.sql`. Тоді виконайте весь вміст `VATRA/vatra-unique-handles-verification.sql`.

**Якщо SQL повідомляє про duplicate existing @handle**, існують акаунти з однаковим @псевдонімом. Міграція навмисно зупиниться, щоб не привласнити чужий псевдонім і не загубити дані. Знайдіть їх:

```sql
select lower(btrim(value ->> 'handle')) as handle,
       array_agg(split_part(path,'/',2)) as user_ids
from public.app_data
where path ~ '^publicProfiles/[^/]+$'
group by lower(btrim(value ->> 'handle'))
having count(*) > 1;
```

Після ручного узгодження конфліктів повторіть міграцію. Жодних акаунтів міграція не видаляє.

## 2. Дати своєму акаунту право видавати галочки

Відкрийте **Supabase → Authentication → Users** та скопіюйте **User UID** свого адміністративного акаунта. Замість прикладного UUID виконайте:

```sql
insert into public.vatra_verification_admins(user_id)
values ('00000000-0000-0000-0000-000000000000')
on conflict do nothing;
```

Ніколи не давайте звичайним користувачам INSERT/UPDATE у `vatra_verification_admins`. Це окрема захищена таблиця. Потрібно підставити СВІЙ UUID (приклад вище сам по собі нікому права не дає).

## 3. Видавати / забирати

Увійдіть на сайт ВАТРА тим акаунтом, чий UUID ви додали, відкрийте **Налаштування профілю → Верифікація офіційних акаунтів**.

Впишіть, наприклад, `@example.handle` і натисніть **«Видати галочку»** або **«Забрати галочку»**. Перед операцією з'явиться підтвердження. Панель з'являється лише за наявності дозволу й встановленої міграції.

Серверна RPC `vatra_set_verification_by_handle` знаходить поточний @псевдонім, визначає UUID користувача і записує `verifiedUsers/<UUID>`. **Зміна псевдоніма не забирає галочку.** Для відкликання вкажіть актуальний @псевдонім користувача.

## 4. Перевірка

1. Спробуйте встановити такий самий @псевдонім у двох різних акаунтах — другому має бути відмовлено (незалежно від регістру).
2. Видайте галочку тестовому акаунту та оновіть сторінку — синя SVG-галочка має бути поруч із ПІБ.
3. Змініть @псевдонім тестового акаунта — галочка повинна залишитися.
4. Відкличте галочку за НОВИМ псевдонімом — вона має зникнути.
5. Переконайтеся, що звичайний користувач не може ні встановити `verifiedUsers/<UUID>`, ні створити собі право адміністратора.

Клієнтський код і SQL-файл у GitHub **не означають застосування SQL до живого Supabase**. Реальну перевірку на двох акаунтах виконайте після встановлення міграції.
