# ВАТРА — нова верифікація, команда та ролі (31.10.2026)

## Порядок встановлення у Supabase

Для нової адмінпанелі потрібні **чотири** SQL-файли, що виконуються через Supabase → SQL Editor у такому порядку:

1. `VATRA/app-data-schema.sql` — базова структура, якщо вона ще не встановлена.
2. `VATRA/vatra-unique-handles-verification.sql` — унікальні @псевдоніми та початкова верифікація акаунтів.
3. `VATRA/vatra-moderation-center.sql` — скарги, блокування, журнал і модерація.
4. **`VATRA/vatra-staff-verification.sql` — власник, ролі працівників, верифікація спільнот, заявки, відповіді та сповіщення.**

**Обережно:** повторний запуск базового `app-data-schema.sql` може скинути RLS-політики `app_data`. Після нього треба повторно застосувати решту міграцій у наведеному порядку. Не запускайте базовий SQL без необхідності на живому сайті.

### Прив’язати власника саме до вашого UID

Після міграції №4 відкрийте **Supabase → Authentication → Users**, скопіюйте **свій User UID** (не псевдонім), і виконайте окремий запит, замінивши приклад на свій UUID:

```sql
insert into public.vatra_network_owners(user_id)
values ('00000000-0000-0000-0000-000000000000')
on conflict do nothing;
```

**Не передавайте цей UUID стороннім.** Власник задається лише через SQL Editor / довірений сервер. Звичайні користувачі не можуть самі себе призначити власниками. Попередній запис у `vatra_verification_admins` не робить акаунт власником автоматично.

## Посади й повноваження

| Роль | Дозволені дії |
|---|---|
| **Власник** | Усі функції адмінпанелі, призначення та відкликання посад |
| Адміністратор | Розгляд скарг, блокування акаунтів і спільнот, приховування контенту, верифікація |
| Модератор | Розгляд скарг, приховування і відновлення контенту |
| Техпідтримка | Перегляд скарг, надання відповіді та зміна їхнього статусу |
| Верифікатор | Видача/відкликання галочок і розгляд заявок на верифікацію |

Власник відкриває **Налаштування → Адмінпанель ВАТРИ → Команда**, вводить UID і обирає посаду. Можна змінювати ролі й знімати права. Кнопки відображаються за роллю, але остаточну перевірку **всіх адміністративних RPC виконує Supabase**.

## Галочки і заявки

- Кожен авторизований користувач має в налаштуваннях **Верифікація → Подати заявку** на свій акаунт.
- **Лише творець спільноти** може подати заявку на свою спільноту за її ID.
- Заявки з'являються у вкладці **«Заявки»**, доступній власнику, адміністратору й верифікатору. Після рішення користувач отримує повідомлення у сповіщеннях.
- У вкладці **«Галочки»** можна видати статус акаунту за поточним @псевдонімом та спільноті за ID.
- Верифікація акаунта закріплюється за UID, спільноти — за ID. Зміна імені, псевдоніма або назви спільноти не прибирає галочку.
- Наведення на галочку показує пояснення і шлях на сторінку **`#/verification`**.
- Видача галочки через серверну RPC відправляє сповіщення підтвердженому користувачу або власнику спільноти. Відмова в заявці також дає відповідь.
- Адмінпанель не дозволяє призначати права будь-кому за @псевдонімом — для ролей використовується тільки справжній Auth UID.

## Тестування

Після SQL-міграції і публікації сайту перевірте:
1. Увійдіть під власним UID. У налаштуваннях має бути **Адмінпанель ВАТРИ**, вкладка **Команда**.
2. Створіть тестовий акаунт і спільноту. Переконайтеся, що інший користувач не може подати заявку на вашу спільноту.
3. Подайте заявки й схваліть їх у вкладці «Заявки». Перевірте сині галочки в профілі, спільнотах, меню та сповіщення про рішення.
4. Призначте тестовий UID техпідтримкою, модератором та адміністратором по черзі. Перевірте відсутність заборонених операцій **не тільки в інтерфейсі, а й при прямому виклику RPC**.
5. Відкличте посаду: після оновлення сторінки адмінпанель має зникнути.
6. Перевірте фотоперегляд із правою панеллю на великому екрані та на телефоні.
7. Перевірте відкриття `#/verification` в новій вкладці.

**Готові зміни GitHub ≠ застосовані SQL чи перевірка в живому браузері.** Не тестуйте бани на основному акаунті. Повне вимкнення входу Supabase Auth, доступ до особистих E2EE-повідомлень і розсилання push-сповіщень при закритому сайті ці зміни не реалізують.
