# Брендування підтвердження ВАТРИ

> **Поточний режим ВАТРИ — реєстрація та вхід за паролем без коду.** У Supabase потрібно вимкнути Confirm email / Confirm phone; інакше UI покаже інструкцію змінити налаштування, а не відкриє крок OTP. Власна Edge Function `vatra-otp` у цій гілці не використовується. Цей файл — лише довідка для майбутнього альтернативного варіанту, якщо власник свідомо вирішить повернути підтвердження.

Цей файл пояснює, що потрібно налаштувати поза фронтенд-кодом. Не вставляй секретні ключі в HTML або JavaScript.

## Довідка для випадку, якщо підтвердження колись буде повернуто

Ці кроки не потрібні для поточного режиму без коду.

## Що можна зробити стандартними засобами Supabase

### Листи підтвердження

1. Відкрий Supabase Dashboard → Authentication → Email → SMTP Settings.
2. Підключи власний SMTP-провайдер і адресу відправника на домені, який ти контролюєш.
3. Задай ім'я відправника **ВАТРА** та адресу на кшталт `no-reply@твій-домен`.
4. У Authentication → Email Templates відредагуй шаблон підтвердження, щоб у темі й тексті була назва ВАТРА.
5. Переконайся, що домен підтверджений у SMTP-провайдера, і перевір доставлення у звичайну пошту та «Спам».

За стандартної Supabase OTP-перевірки код `{{ .Token }}` — це код, який Supabase згенерував і перевіряє. Не замінюй його випадковим кодом, створеним лише в браузері: це не пройде перевірку і може зробити підтвердження небезпечним.

## SMS-повідомлення

1. Відкрий Supabase Dashboard → Authentication → Phone.
2. Увімкни phone provider і підключи підтримуваного SMS-провайдера з власними обліковими даними.
3. Налаштуй шаблон SMS із токеном Supabase та перевір доставлення на реальний номер.
4. Ім'я відправника SMS залежить від провайдера, країни, типу номера й локальних правил. Не кожен провайдер дозволяє показувати текстове ім'я «ВАТРА»; іноді відображається короткий номер.

## Якщо потрібен буквено-цифровий код

Стандартний Supabase Phone/Email OTP не можна довільно замінити на код, згенерований фронтендом. Для власного буквено-цифрового коду потрібен серверний процес (наприклад, Supabase Edge Function), який:
- генерує криптографічно випадковий код;
- зберігає лише його хеш із коротким терміном дії;
- обмежує кількість надсилань і спроб перевірки;
- надсилає лист через SMTP/API або SMS через підключений провайдер;
- перевіряє код на сервері й лише після успіху завершує створення акаунта.

Для цього потрібні секрети провайдера, які слід додати в Supabase Edge Function Secrets — ніколи не в репозиторій. Також потрібно змінити потік реєстрації та перевірки в застосунку. Не вмикай власну перевірку, доки серверний endpoint не розгорнуто й не протестовано.
