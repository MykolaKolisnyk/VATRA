# ВАТРА — передзапускова перевірка

Цей список відділяє те, що можна перевірити в репозиторії, від того, що потребує реального браузера та доступу до Supabase. Не вважай пункт пройденим, доки не перевірено фактичний результат.

## 1. Автоматичні перевірки репозиторію

- [ ] GitHub Actions workflow **VATRA checks** завершився успішно.
- [ ] JavaScript-модулі проходять синтаксичну перевірку.
- [ ] Регресійні перевірки підтверджують наявність основних auth-функцій, RLS-політик і обмежень завантаження медіа.

Ці перевірки не підтверджують, що Supabase налаштований або що інтерфейс працює в браузері.

## 2. Supabase — перед тестуванням

Відкрий Supabase Dashboard для проєкту ВАТРИ та перевір:

- [ ] У **SQL Editor** виконано актуальний `app-data-schema.sql` із репозиторію. Перед повторним запуском переглянь SQL та переконайся, що це саме очікуваний проєкт.
- [ ] У Database → Tables існує `public.app_data`, а RLS увімкнено.
- [ ] У Database → Policies є політики читання/запису `app_data` та політики для `storage.objects`.
- [ ] У Storage існує bucket `vatra-media`; перевірені ліміт 50 MiB і дозволені MIME-типи.
- [ ] У Authentication → URL Configuration задані правильні Site URL і Redirect URLs для фактичного домену ВАТРИ.
- [ ] В Authentication → Providers увімкнені лише потрібні способи входу.
- [ ] Для публічного email-запуску налаштований власний SMTP, перевірено лист відновлення пароля.
- [ ] Для входу/відновлення телефоном налаштовані Phone provider та SMS-провайдер. Без цього SMS-потік не готовий.
- [ ] Перевірено Supabase Security Advisor. RLS не вимикати; service-role/secret key не додавати до клієнтського JavaScript.

**Важливо про підтвердження контакту:** поточний звичайний потік реєстрації очікує сесію одразу після створення акаунта. Якщо Supabase вимагає підтвердження email/телефону, UI покаже помилку конфігурації. Не обходь це в коді. Для публічного запуску краще налаштувати належне підтвердження контакту та адаптувати потік реєстрації, а не вимикати його заради зручності.

## 3. Ручні перевірки у браузері

Виконуй на тестових акаунтах, спершу на staging або з тестовими даними.

### Вхід і реєстрація
- [ ] Відкрити `auth.html`: за замовчуванням вибраний спосіб входу відповідає полю контакту.
- [ ] Перемкнути email ↔ телефон кілька разів: поле, підпис і код країни змінюються коректно; зайвого другого скролу немає.
- [ ] Перевірити короткий/слабкий пароль, різні паролі підтвердження, некоректний email і номер телефону.
- [ ] Перевірити вік: дата в майбутньому та вік до 13 років відхиляються.
- [ ] Відкрити кожен документ: Правила спільноти, Політика конфіденційності, Умови використання.
- [ ] Зареєструвати тестовий акаунт і переконатися, що профіль створений один раз.
- [ ] Вийти й увійти повторно.
- [ ] Перевірити відновлення пароля email-посиланням. Телефонний потік перевіряти лише після налаштування SMS.
- [ ] Перевірити вхід із уже авторизованою сесією та відкриття юридичних документів.

### Дані, медіа й права доступу
- [ ] Створити текстову публікацію; перезавантажити сторінку й переконатися, що запис зберігся.
- [ ] Завантажити дозволене фото та коротке відео; перевірити, що файл відображається після повторного входу.
- [ ] Перевірити перевищення ліміту розміру та заборонений тип файлу.
- [ ] Перевірити видимість публічного, приватного та дружнього допису двома різними акаунтами.
- [ ] Перевірити лайк, коментар, збереження та видалення власної публікації.
- [ ] Перевірити запит у друзі, прийняття/відхилення та видимість профілю.
- [ ] Перевірити створення спільноти, приєднання, ролі та доступ до приватної спільноти.
- [ ] Перевірити повідомлення між двома тестовими акаунтами й переконатися, що сторонній акаунт не читає чужий чат.
- [ ] Перевірити блокування та скаргу.
- [ ] Увійти з другого акаунта та переконатися, що він не може редагувати чи видаляти чужі дані.

### Різні екрани та стабільність
- [ ] Перевірити актуальні Chrome/Opera на Windows і Safari на iPhone.
- [ ] Перевірити вузький екран, клавіатуру телефону, довгі імена та помилки мережі.
- [ ] Переглянути Console і Network: немає необроблених помилок JavaScript, 401/403/404 або помилок Storage.
- [ ] Перевірити логи Supabase Auth, Database і Storage після тесту.

## 4. Критерій готовності

ВАТРУ не слід оголошувати готовою до публічного запуску, доки критичні пункти входу, збереження даних, приватності/RLS, медіа та відновлення акаунта не пройдені на живому середовищі. Наявність коду або успішний CI самі по собі не є підтвердженням працездатності.
