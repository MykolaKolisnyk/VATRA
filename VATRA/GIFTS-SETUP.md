# Подарунки ВАТРИ · запуск ручних замовлень

## Порядок запуску в Supabase (Production)
1. Спершу застосувати `VATRA/app-data-schema.sql` і `VATRA/vatra-staff-verification.sql` / SQL, що створює `public.vatra_staff_role()`.
2. Переконатися, що вже виконано `VATRA/vatra-support-desk.sql` — офіційні повідомлення про замовлення надсилатимуться через техпідтримку ВАТРИ.
3. Один раз застосувати `VATRA/vatra-gifts.sql` (базові таблиці подарунків, приватність, передавання друзям, святкові подарунки).
4. Потім один раз застосувати **`VATRA/vatra-gifts-orders.sql`** (ціни, вітальний подарунок, замовлення, адмін-видавання/відкликання за @псевдонімом, журнал, офіційне повідомлення від ВАТРИ). Цю міграцію не потрібно повторно запускати після успішного застосування: частина команд додає обмеження БД. Для повторних змін слід робити окрему міграцію.

## Як користується гість / учасник
- Після першого входу ВАТРА безкоштовно нараховує «Першу іскру ВАТРИ» незалежно від того, чи акаунт зареєстрований давно. На кожен UID подарунок лише один раз.
- 31 жовтня, 1 січня, 24 серпня користувач може отримати безкоштовний святковий подарунок. Повторний виклик безпечний.
- У профілі, **під блоком друзів**, розміщується «Подарунки» і кнопка «Усі подарунки». Пункт у загальній навігації **відсутній**.
- У каталозі: Мої, Безкоштовні, Платні, Замовлення. Платні подарунки мають явну ціну у гривнях; приклад «Золотий гарбуз» — **20 грн**.
- Кнопка «Замовити» лише створює заявку; **не списує грошей**. Заявка фіксує ціну на момент замовлення. Замовлення є в адмінпанелі.
- У профілі можна налаштувати приватність подарунків: «Для всіх», «Для друзів», «Лише для мене». SQL перевіряє доступ для відвідувача.
- Подарунок можна передати другу, якщо він належить користувачу. Передавання не дублює подарунки.

## Дії власника
- Адмінпанель → «Замовлення подарунків»: бачити UID, @псевдонім, ціну, статус заявки; написати офіційне повідомлення ВАТРИ, домовитися про зручну оплату (переказ чи особиста зустріч), після фактичної оплати натиснути «Оплату отримано · Видати».
- Подарунок видається атомарно; одне замовлення не може породити два подарунки.
- Є ручне видавання **за @псевдонімом**: сервер знаходить точний профіль, записує незмінний UID і унікальний ID виданого екземпляра подарунка.
- Для відкликання спершу знайти користувача за @псевдонімом, потім забрати конкретний подарунок за його ID. Дія записується до аудиту. Самостійне створення/вилучення подарунків клієнтом заборонено.
- Офіційні повідомлення проходять через `vatra_support_tickets` та `vatra_support_messages`. Користувач бачить їх у техпідтримці.

## Важливо
Ці SQL-файли додані до GitHub, **не виконані автоматично в робочому Supabase**. Без запуску міграцій видавання, замовлення та вітальні подарунки не запрацюють. Ціни зараз налаштовані в SQL і каталозі; при зміні необхідно оновлювати обидва джерела синхронно. Автоматичного платіжного шлюзу немає. Зберігати номери карток або дані клієнтських платежів у ВАТРІ не потрібно.

## Скасування замовлень (оновлення 31.10.2026)
Після базових SQL-файлів застосуйте **VATRA/vatra-gifts-order-cancellation.sql**. Скасування незавершеного замовлення тепер використовує `DELETE` у транзакції. Власник також може відхилити й видалити невиконане замовлення в адмінпанелі. Раніше скасовані (`status='cancelled'`) заявки видаляються під час міграції. **Перед міграцією зробіть резервну копію**: очищення старих скасованих заявок незворотне. Виконані замовлення та фактично видані подарунки не зачіпаються.
