# ВАТРА — налаштування авторизації Supabase (без кодів)

У цій версії ВАТРИ звичайний вхід і реєстрація виконуються за email або номером телефону та паролем. **OTP-код не запитується під час входу чи реєстрації.** Сесію зберігає Supabase у браузері; окремий список збережених контактів не потрібен.

## 1. Обов’язкові налаштування Supabase

Відкрий саме той Supabase-проєкт, URL якого вказаний у `vatra-backend.js`.

1. У Authentication → Settings / General залиш увімкненим **Allow new users to sign up**.
2. У Authentication → Sign In / Providers → Email вимкни **Confirm email**.
3. Якщо потрібна реєстрація за номером, увімкни **Phone provider**, але вимкни **Confirm phone**.
4. Збережи налаштування і протестуй новий унікальний контакт. Після реєстрації Supabase має повернути активну сесію.

Якщо після реєстрації немає сесії, ВАТРА зупиняє процес і показує підказку про налаштування підтвердження. Не обходь цю перевірку створенням клієнтської сесії вручну. Назви пунктів у Dashboard можуть трохи відрізнятися між версіями інтерфейсу.

## 2. Унікальність контактів і безпека

- Supabase Auth перевіряє унікальність email і номера. ВАТРА обробляє відповідь Supabase про вже зайнятий контакт.
- Не роби відкритий запит для пошуку акаунтів за email/телефоном до реєстрації — він може розкрити, хто зареєстрований.
- **Компроміс без OTP:** адреса або номер не підтверджуються як такі, що справді належать людині. Можна помилитися в контакті, а номер може бути переданий іншій людині. Це ризик обраного режиму без коду.
- Інтерфейсна «Швидка перевірка» не замінює серверну CAPTCHA. Для публічного запуску ввімкни серверний захист від ботів, ліміти запитів і моніторинг зловживань.

## 3. Паролі

ВАТРА перевіряє мінімум 12 символів, малу латинську літеру (a–z), велику (A–Z), цифру та спецсимвол. Краще використовувати унікальний пароль із 16–20 випадкових символів або довгу парольну фразу з менеджера паролів. Приклад у формі показує формат, але його не слід копіювати дослівно. У Supabase Password security налаштуй серверні вимоги до пароля й перевірку витоків, якщо вона доступна у твоєму плані.

## 4. Відновлення доступу

Відновлення пароля є окремою функцією та може надсилати лист або SMS відповідно до вибраного способу. Для email перевір SMTP, шаблон Reset Password і Authentication → URL Configuration (redirect на `auth.html?mode=new-password`). Для SMS потрібні ввімкнений Phone provider, налаштований SMS-провайдер, баланс і дозвіл відправлення в Україну. Це не впливає на звичайний вхід за паролем.

## 5. Помилки даних і секрети

Якщо не працюють дописи чи збереження даних, виконай актуальний `VATRA OLD/app-data-schema.sql` у Supabase SQL Editor саме в тому проєкті, URL якого вказаний у `vatra-backend.js`. Не вимикай Row Level Security для обходу помилок.

Не додавай у браузерний код Supabase service-role key, SMTP-пароль, поштові API keys чи Twilio auth token. У фронтенді може бути лише публічний publishable/anon key.
