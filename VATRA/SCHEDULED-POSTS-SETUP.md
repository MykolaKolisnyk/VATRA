# ВАТРА: автоматичне планування публікацій (Supabase)

Працює в однаковому редакторі для профілю та спільноти. Потрібне **одноразове серверне налаштування** — без нього кнопка «Запланувати допис» показуватиме помилку і не робитиме неправдивих обіцянок.

## 1. Міграція PostgreSQL

Відкрийте Supabase-проєкт `rjasunoawrxvetwadylh`. У SQL Editor виконайте
[vatra-scheduled-posts.sql](vatra-scheduled-posts.sql).

Міграція створює таблицю `public.vatra_scheduled_posts` із RLS. Користувач бачить і скасовує **тільки власні** заплановані публікації. Змінити автора, текст, час або спільноту після створення через клієнт не можна. Спільнота перевіряється під час постановки в чергу і повторно перед виходом допису.

Перевірте застосування [vatra-community-settings-rls.sql](vatra-community-settings-rls.sql), щоб правила учасників та коментарів перевірялися на сервері.

## 2. Запуск щохвилини без браузера

У Supabase Database → Extensions увімкніть `pg_cron`, якщо він іще не активний.
Після цього **один раз** у SQL Editor:

```sql
select cron.schedule(
  'vatra-publish-scheduled-posts',
  '* * * * *',
  $$select public.vatra_publish_due_posts(100);$$
);
```

Перевіряйте запуски в Dashboard → Cron → History. Один прохід обробляє до 100 запланованих публікацій, тому за великої черги вони можуть виходити пізніше; сервіс працює з точністю до хвилини, **не до секунди**.

Для перевірки використайте окремий тестовий акаунт:
- Заплануйте текстовий допис через 3–5 хвилин і закрийте вкладку.
- Перевірте, що до вказаного часу допису немає в стрічці.
- Перевірте, що після запуску Cron допис з’являється один раз і має фактичний час публікації.
- Перевірте опитування, фото, відео та авторство спільноти; окремо — скасування ще не опублікованого допису.
- Перевірте налаштування прав: звичайний учасник не може запланувати допис від спільноти чи обійти вимкнення публікацій.

## 3. Дата, медіа та часовий пояс

Дата й час вибираються в локальному часовому поясі пристрою автора. Браузер передає ISO UTC, PostgreSQL зберігає `timestamptz`. У списку запланованих дописів показуємо місцевий час поточного пристрою.

Медіафайли перед постановкою в чергу завантажуються в `vatra-media`, а на дату публікації сервер створює допис за збереженими посиланнями. Скасування допису **не видаляє** попередньо завантажені фото/відео автоматично. Для повного прибирання таких медіафайлів потрібне окреме серверне прибирання після перевірки, що їх не використовує інший допис.

## 4. Безпека

Ні сервісний ключ Supabase, ні права `service_role` не видаються браузеру. RLS не вимикається. `vatra_publish_due_posts()` доступна тільки серверній ролі. Браузер може створювати, переглядати й скасовувати **власні** заплановані дописи.
