# Налаштування входу та публікації ВАТРИ

> **Історична інструкція для режиму з OTP.** Поточна версія реєструє через пароль без коду. Для цього спочатку виконайте кроки у `SUPABASE-AUTH-SETUP.md` і вимкніть Confirm email та Confirm phone. Розділи нижче потрібні лише якщо Ви навмисно повернете підтвердження.

Цей файл описує налаштування, які не можна змінити лише кодом сайту: шаблони листів і провайдери в Supabase.

## 1. Щоб email надсилав саме 6-значний код, а не посилання

1. Відкрийте Supabase Dashboard і проєкт ВАТРИ.
2. Authentication → Email Templates → **Confirm signup**.
3. У шаблоні листа замініть посилання на підтвердження на код:
   `{{ .Token }}`
4. Текст листа може бути таким:

   **Тема:** Код підтвердження ВАТРИ

   **Тіло:**
   `Ваш код підтвердження ВАТРИ: {{ .Token }}`

   `Код діє обмежений час. Не передавайте його іншим людям.`

5. Збережіть шаблон і перевірте реєстрацію новою адресою. Якщо у шаблоні залишити `{{ .ConfirmationURL }}`, Supabase надсилатиме посилання, а не код.

## Важливо: чому email-код може не приходити

За замовчуванням Supabase не є повноцінним поштовим сервісом для всіх користувачів. Без власного SMTP він надсилає листи лише на попередньо дозволені адреси команди проєкту та має дуже низький ліміт відправлення. Тому зміни в HTML/JS не можуть змусити Supabase надсилати листи будь-кому.

Щоб реєстрація працювала для звичайних адрес:
1. Створи обліковий запис у поштового сервісу (наприклад Resend, Brevo або інший SMTP-сервіс).
2. Підтверди домен відправника у цього сервісу, якщо це вимагається.
3. У Supabase відкрийте Authentication → SMTP Settings (розділ може називатися SMTP) і ввімкніть власний SMTP: host, port, username, password, sender email та sender name.
4. Для бренду листа використовуйте ім’я відправника «ВАТРА» і шаблон із заголовком «Код підтвердження ВАТРИ».
5. Не публікуйте SMTP-пароль, API key або service-role key у коді браузера чи GitHub.

Якщо Ви не бачите цих налаштувань або не можете їх зберегти, потрібні права власника/адміністратора проєкту Supabase. Репозиторій GitHub не може змінити налаштування Auth в Supabase автоматично.

## 2. SMS-код

1. Authentication → **Providers** → Phone: увімкніть Phone provider.
2. Налаштуйте SMS-провайдера (наприклад Twilio) і підтвердьте його облікові дані та sender.
3. У SMS Template використовуйте код `{{ .Code }}`, наприклад: `Код підтвердження ВАТРИ: {{ .Code }}`.
4. Переконайтеся, що в провайдера дозволене надсилання SMS в Україну (+380) та що баланс/ліміти не вичерпані.

Якщо провайдер не налаштований, код із фронтенду не зможе самостійно доставити SMS. Для тестів Supabase може мати власні обмеження й тестові номери.

## 3. Помилка «Запит відхилено правилами доступу до бази даних» під час публікації

1. Відкрийте SQL Editor саме в проєкті ВАТРИ.
2. Відкрийте файл `VATRA OLD/app-data-schema.sql` у цій гілці GitHub.
3. Скопіюйте **весь** SQL-файл, виконайте його одним запуском і перевірте, що внизу немає червоної помилки.
4. Перезавантажте сайт, вийдіть, увійдіть знову та спробуйте опублікувати звичайний текстовий допис без фото.

SQL-файл містить політики RLS для `public.app_data` і окрему перевірку власника допису. Не вимикайте RLS і не додавайте відкриті політики на запис для `anon`.

Якщо помилка залишається, відкрийте DevTools → Network, знайдіть невдалий запит до `app_data` і зафіксуйте HTTP status та код помилки Supabase (не копіюйте access token, пароль або ключі). Це дозволить відрізнити невиконаний SQL від проблеми з UID/політикою.

## 4. Пароль у реєстрації

Форма ВАТРИ тепер перевіряє пароль на 12+ символів, малу й велику латинські літери, цифру та спеціальний символ. Це рекомендація ВАТРИ для сильнішого пароля, а не гарантія абсолютного захисту. Використовуйте унікальний пароль і не повторюйте його на інших сайтах.
