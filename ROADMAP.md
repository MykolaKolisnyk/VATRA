# ВАТРА — план міграції та запуску

## Етап 1 — Supabase основа
- [x] Підготувати клієнт Supabase без Firebase SDK у активній версії.
- [x] Перенести форму входу/реєстрації на Supabase Auth.
- [x] Підготувати SQL-таблиці та RLS-політики.
- [x] Підключити базові операції профілю, дописів, лайків, коментарів, збереженого, дружби, спільнот і повідомлень.
- [x] Додати основу опитувань, сповіщень і скарг.
- [x] Оновити адаптивні стилі.

## Етап 2 — обов’язкова перевірка
- [ ] Виконати `vatra-v9/supabase-schema.sql` у Supabase SQL Editor.
- [ ] Перевірити реєстрацію з підтвердженням пошти та автоматичне створення профілю.
- [ ] Перевірити права двох тестових користувачів на приватні профілі, дописи, повідомлення й спільноти.
- [ ] Перевірити завантаження медіа й ліміти розміру.
- [ ] Перевірити, що користувач не може читати чи змінювати чужі приватні записи.
- [ ] Після успішних тестів злити міграційну гілку в основну.

## Етап 3 — покращення продукту
- [ ] Повний UX приватності профілю й керування аудиторією дописів.
- [ ] Перегляд та модерація скарг для адміністратора.
- [ ] Окремий перегляд спільноти з дописами та керуванням учасниками.
- [ ] Пошук і нові розмови без ручного введення ID користувача.
- [ ] Перевірка продуктивності медіа; Base64 не є шифруванням і може збільшувати розмір записів.

Міграція не вважається завершеною лише через наявність коду: її потрібно перевірити на реальній базі.
