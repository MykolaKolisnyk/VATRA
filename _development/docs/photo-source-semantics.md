# VATRA фотографії: джерело, коментарі, прогресивне завантаження

Завантажена користувачем відеодемонстрація VK (2026-11-22, 142 с) показує
просте завантаження фотографій, створення і редагування альбомів, вибір
видимості та вкладку «Фотографії». VATRA має зберігати зв’язок із джерелом.

| Джерело фотографії | Підпис у переглядачі | Коментарі | Реакції |
| --- | --- | --- | --- |
| Аватар / історія аватарів | Фото профілю | `avatar_comments`, ключ `owner_vatra_id+avatar_path` | `avatar_likes` |
| Фото з допису | Фото з публікації | `post_comments` за `post_kind+post_id` | `post_likes` за тим самим дописом |
| Пряме додавання без публікації | Фото користувача | `photo_album_comments.photo_id` | `album_photo_likes.photo_id` |
| Фото з вибраного альбому | Фото з альбому «Назва» | `photo_album_comments.photo_id` | `album_photo_likes.photo_id` |
| Обговорення самого альбому | Коментарі альбому | `photo_album_comments.photo_id IS NULL` | немає |

Вкладка «Фотографії» показує джерела за окремими блоками; наступний крок
після регресійних перевірок — один відсортований за часом потік з єдиною
курсорної пагінацією. Джерела не копіюються у другу таблицю коментарів;
при відкритті повторно використовуються оригінальні дозволи RLS.

Пряме додавання автоматично створює приватно-керований системою альбом
`is_personal=true` лише один раз на власника. Користувач не зобов’язаний
спочатку створювати альбом чи публікацію. Вміст зберігається в
`album-photos` з чинними Storage RLS.

Історія аватарів вантажиться порціями по 24 записи з Storage.list.
Фото альбомів вантажаться по 18, вибірки джерел за публікаціями по 6,
попередні фото з альбомів по 12, коментарі до фото — по 10.
Усі медіафайли завантажуються лише під час наближення до видимої області;
одночасні завантаження нових фото обмежені двома. Під час додавання
коментаря створюється локальний рядок «Публікується…», який після успіху
замінюється фактичним коментарем без повного повторного завантаження.
Немає загального «1000 за раз» на звичайних сторінках; guard на 1000
під час *видалення альбому* — захист від неповного очищення, не пагінація.

Права доступу залишаються у Supabase RLS; Redis Cloud Free без TLS
не отримує приватні альбоми, медіа-посилання, коментарі чи лайки.

## Дії з фотографією та однаковий переглядач

- Фотографії альбомів і прямі фотографії користувача використовують таку
  саму структуру переглядача, як фотографії публікацій: велике зображення
  зліва, інформація про автора та взаємодії справа, нижня панель дій.
- На кожній мініатюрі альбомного фото доступне меню `•••`; у
  повноекранному перегляді — `Більше`. Дії:
  **Завантажити** (через авторизоване Storage.download),
  **Перейти до альбому**, **Поділитися** (посилання на фото),
  **Закріпити/Відкріпити** (лише власник),
  **Видалити** (лише власник, з підтвердженням).
- `album_photos.pinned_at` індексується за альбомом. Політика UPDATE
  доступна лише власнику, а тригер забороняє зміну ідентичності фото,
  альбому, шляху файлу та часу створення через API.
- Посилання `?album=<uuid>&photo=<uuid>` відкриває конкретне фото лише
  після проходження RLS-перевірки запиту. Публічних URL приватних
  фотографій у клієнті немає; тимчасові підписані URL залишаються тільки
  у пам'яті поточного користувача.
- Для фото профілю у `Більше` додані **Завантажити** та **Перейти до
  альбому**. Автор власного коментаря на аватарі може його видалити;
  запит DELETE додатково обмежений `author_id=auth.uid()` через RLS.

## Завантаження і швидкодія

- Після вибору файлів користувач бачить реальні картки зображень та статус
  кожного файлу: у черзі, завантажується, завантажено або помилка.
- Індикатор показує число завершених файлів (загалом не більше 8),
  **не вигаданий байтовий відсоток**: стандартний Supabase Storage
  `upload()` у цій реалізації не надає побайтових подій прогресу.
- Паралельно йдуть максимум два файли. Помилка одного файлу не
  приховує підсумок інших і не вимагає перезавантаження сторінки.
- Поки тимчасова URL для перегляду фото підписується і зображення
  завантажується, показується стан «Завантаження фотографії…».
