# VATRA: завантаження функцій за потреби (2026-11-22)

## Контракт сторінок

`profile.html` і `feed.html` містять основні для маршруту JS/CSS та невеликий
`assets/js/feature-loader.js`. На старті **не** завантажують редактор історій,
додатковий інтерфейс редактора публікації або його стилі. Профіль також не
завантажує код/стилі альбомів, доки користувач не відкриє вкладку.

- `story` → `story-editor.css` → `story-editor.js`, після кнопки «Створити історію»
- `composer` → `post-composer.css` → `post-composer-ui.js`, після відкриття редактора допису
- `albums` → `photo-albums.css` → `photo-albums.js`, після вкладки «Фотографії»
- Запит `?album=<uuid>&photo=<uuid>` на профілі одразу підключає альбоми, з
  перевіркою доступу у Supabase RLS, без копіювання приватних даних у кеш.

Спільний завантажувач запам'ятовує Promise для кожної функції, щоб дві
одночасні дії не завантажували однаковий JS/CSS вдруге; чекає на готовність
CSS перед запуском JS; після мережевої помилки дозволяє повторити дію.
Додавання нової функції до loader не означає її автоматичне завантаження.

## Межі першої оптимізації

- `gift-viewer.js`/каталог подарунків поки залишені у профілі: каталог
  використовується також у первинних картках, тож його потрібно окремо
  відділити від повноекранного переглядача.
- `post-media.js`, `post-interactions.js` та `profile.js` поки залишені
  як залежності основних сторінок. Подальше дроблення можливе після
  аудиту ініціалізації, підписок і підписаних медіапосилань.
- Основні CSS сторінки залишаються в HTML, щоб не спричинити стрибки
  верстки (FOUC). CSS модальних редакторів підключається **до** їх відкриття.
- При зміні fingerprints оновлювати шляхи у `feature-loader.js` та його
  `?rev=` в HTML, щоб уникати застарілих файлів у кеші браузера.

Тести: `feature-loader-smoke.mjs`, `photo-albums-smoke.mjs`, аудит
`check-layout.mjs` та Playwright у GitHub Actions. Жодних змін Supabase,
Redis Secrets, даних користувачів або RLS для цієї оптимізації не потрібно.
